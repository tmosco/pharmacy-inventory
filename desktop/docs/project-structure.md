# Project Structure Guide

This project is a desktop app built with three main pieces:

- React for the user interface
- Vite for the frontend development and build process
- Tauri + Rust for the native desktop shell

Use this guide when an error message points to a file and you want to quickly understand what that file is responsible for.

## Top-level folders and files

### `src/`

This is the frontend application code. It is where the React user interface lives.

- Add new pages, screens, components, hooks, and frontend logic here.
- If you want to change what the user sees, this is usually the first place to look.

Important files in `src/`:

- `src/main.tsx`: Starts the React app and mounts it into the HTML page.
- `src/App.tsx`: The main React component right now. In this starter app it shows the welcome screen and calls a Rust command.
- `src/App.css`: Styles for the current React UI.
- `src/assets/`: Images or other frontend assets imported by React code.
- `src/vite-env.d.ts`: TypeScript helper file so Vite types are available in the frontend.

### `src-tauri/`

This is the native desktop side of the app. It contains Rust code, Tauri configuration, permissions, icons, and generated native build files.

- If you want to add a native command, desktop capability, or packaging setting, you usually work here.
- React runs in the app window, but Tauri and Rust are what turn it into a desktop application.

Important files and folders in `src-tauri/`:

- `src-tauri/src/`: Rust source code for the desktop backend.
- `src-tauri/src/main.rs`: Native entry point that starts the app.
- `src-tauri/src/lib.rs`: Main Tauri setup. This is where commands, plugins, and the app builder are configured.
- `src-tauri/Cargo.toml`: Rust manifest file. It lists Rust dependencies and crate settings.
- `src-tauri/Cargo.lock`: Locked Rust dependency versions for repeatable builds.
- `src-tauri/build.rs`: Rust build script. Here it runs `tauri_build::build()` so Tauri can prepare native build metadata.
- `src-tauri/tauri.conf.json`: Main Tauri configuration file for app metadata, window settings, build commands, and bundle settings.
- `src-tauri/capabilities/`: Tauri capability and permission files.
- `src-tauri/capabilities/default.json`: The current capability file for the main window. It allows the default core permissions and the opener plugin permissions.
- `src-tauri/icons/`: Application icons used when the desktop app is bundled for different operating systems.
- `src-tauri/gen/`: Generated schema files used by Tauri tooling. Helpful for validation, but usually not edited by hand.
- `src-tauri/target/`: Rust build output. This is generated during compilation and should not be treated as source code.

### `public/`

This folder holds static frontend files that are served directly.

- Files here can be referenced by URL, such as `/vite.svg` or `/tauri.svg`.
- Use this for assets that do not need to be imported into React code.

### `package.json`

This is the JavaScript project manifest.

- It defines npm scripts you run during development.
- It lists frontend dependencies and development tools.

Important scripts in this project:

- `npm run dev`: Starts the Vite frontend dev server.
- `npm run build`: Type-checks and builds the frontend.
- `npm run preview`: Previews the built frontend locally.
- `npm run tauri`: Runs the Tauri CLI.

### `package-lock.json`

This locks exact npm package versions so installs stay consistent across machines.

### `vite.config.ts`

This is the Vite configuration.

- It enables the React plugin.
- It uses port `1420` for Tauri development.
- It tells Vite to ignore watching `src-tauri`, because Rust files are handled by Tauri tooling instead.

### `tsconfig.json`

This is the main TypeScript configuration for the frontend.

- It controls TypeScript rules such as strict checking and JSX support.
- It applies to files inside `src/`.

### `tsconfig.node.json`

This is TypeScript configuration for Node-side files such as `vite.config.ts`.

### `index.html`

This is the single HTML page Vite serves for the React app.

- It contains the `<div id="root"></div>` mount point.
- `src/main.tsx` is loaded from here.

### `README.md`

This currently contains the starter template notes for a Tauri + React + TypeScript app.

### `.gitignore`

This tells Git which generated files should not be committed, such as `node_modules` and `dist`.

### `.vscode/`

This usually stores editor settings for VS Code. It is helpful for team consistency, but it is not part of the app runtime.

### `node_modules/`

This contains installed JavaScript packages. It is generated by npm and should not be edited manually.

## How the app fits together

The flow looks like this:

1. `index.html` loads `src/main.tsx`.
2. `src/main.tsx` renders `src/App.tsx`.
3. React code in `src/` handles the user interface.
4. When React needs native desktop behavior, it can call Rust commands defined in `src-tauri/src/lib.rs`.
5. Tauri uses `src-tauri/tauri.conf.json` and the capability files in `src-tauri/capabilities/` to decide how the desktop app should run and what it is allowed to do.

In the current starter code:

- `src/App.tsx` calls `invoke("greet", { name })`
- `src-tauri/src/lib.rs` defines the `greet` Rust command

That is the basic bridge between the React side and the Rust side.

## What is editable vs generated

Usually edit these:

- `src/`
- `src-tauri/src/`
- `src-tauri/capabilities/`
- `src-tauri/tauri.conf.json`
- `src-tauri/Cargo.toml`
- `package.json`
- `vite.config.ts`
- `tsconfig.json`

Usually do not edit these by hand:

- `node_modules/`
- `dist/` when it exists
- `src-tauri/target/`
- most of `src-tauri/gen/`
- lockfiles unless dependency changes require them

## Checkpoint answers

### Where do I add a React page?

Add it in `src/`.

In a larger app, a common pattern would be something like:

- `src/pages/InventoryPage.tsx`
- `src/components/` for reusable UI pieces

This project does not have a routing or pages folder yet, so you would create that structure inside `src/` when needed.

### Where do I add a database migration?

There is no database or migration folder in this repository yet.

That means the project is not currently set up for migrations. When database support is added, the migration location will depend on the database tool chosen, for example:

- a new top-level `supabase/migrations/`
- a new top-level `prisma/`
- a new top-level `drizzle/`
- a Rust-side database setup under `src-tauri/` if the app uses a native SQLite approach

For now, the right answer is: no migration location exists yet.

### Where do I add a Tauri permission?

Add it in `src-tauri/capabilities/`.

The current permission setup is in:

- `src-tauri/capabilities/default.json`

That file controls what the main window is allowed to use.

### Where do I add an application icon?

Add or replace icons in `src-tauri/icons/`.

Those icon files are referenced by:

- `src-tauri/tauri.conf.json`

## Quick mental model

When you see an error:

- If it mentions React, JSX, CSS, or TypeScript UI files, check `src/`.
- If it mentions Cargo, Rust, Tauri commands, plugins, or native packaging, check `src-tauri/`.
- If it mentions scripts or npm packages, check `package.json`.
- If it mentions Rust crates, check `src-tauri/Cargo.toml`.
- If it mentions app identity, window size, bundling, or icons, check `src-tauri/tauri.conf.json`.
- If it mentions capabilities or permissions, check `src-tauri/capabilities/`.
